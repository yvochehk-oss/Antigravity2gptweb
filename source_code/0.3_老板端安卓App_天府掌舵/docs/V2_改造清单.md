# V2 企业级改造清单

本文区分“已落到仓库的工程基线”和“仍需业务/后端联调的生产能力”。清单完成不等于生产上线。

## 已落地基线

- [x] API、Pinia 状态、离线快照等前端分层目录；
- [x] Capacitor 8 Android 工程与 `dist` Web 资源同步；
- [x] Release 开启 R8 混淆和资源收缩；
- [x] Release 禁止明文 HTTP，禁止混合内容和 WebView 调试；
- [x] 禁止 Android 云备份与设备迁移复制应用数据；
- [x] API 请求支持 Bearer Token，离线快照默认 24 小时过期并在退出登录时清除；
- [x] 本地角色登录仅允许开发模式或显式演示开关，正式构建未接统一认证时拒绝进入；
- [x] Release 签名仅从环境变量注入，仓库不保存 keystore 和口令；
- [x] 调试包与正式 Release 的使用边界写入打包指南。

## 上线前必须完成

- [ ] 接入真实身份服务，完成 Token 刷新、吊销、设备解绑和会话超时；
- [ ] 后端执行 RBAC 与企业/项目/字段级数据权限，前端隐藏菜单不能替代鉴权；
- [ ] 所有经营指标改为服务端权威计算，AI 只解释已签名/可追溯结果；
- [ ] 建立允许访问的生产 HTTPS 域名清单、证书与密钥轮换机制；
- [ ] 对离线快照继续实行最小字段、系统密钥库加密和远程失效；
- [ ] 完成真机、弱网、离线、渗透、依赖和隐私合规测试；
- [ ] 配置正式签名、提升版本号、生成软件物料清单并保留可追溯构建记录；
- [ ] 通过业务负责人、安全负责人和发布负责人三方验收。

## 后续增强

- [ ] 生物识别只用于解锁受系统密钥库保护的本地凭据，不直接充当服务器身份认证；
- [ ] 推送通知默认不携带敏感经营数据，点击后重新鉴权拉取；
- [ ] 崩溃监控、审计日志、远程配置和强制升级策略；
- [ ] AI 答案证据链、权限继承、提示注入防护和人工复核闭环。
