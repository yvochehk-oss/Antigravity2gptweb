# 外部模型 API 与 AI 检查编排架构

## 一、目标

系统允许用户在任何时间主动选择一个项目，对某个环节或整个项目发起AI检查。

支持范围：

- 项目总体
- 预算与成本偏差
- 合同
- 履约证据
- 发票
- 资金与付款
- 真实成本穿透
- 税务管理测算
- EAC预计完工
- 风险
- 材料
- 劳务
- 设备
- 专业分包
- 整个项目

## 二、运行顺序

用户点击“启动检查”
→ 选择项目、检查范围、模型端点
→ 输入特别要求
→ 本地确定性引擎先计算
→ 按范围抽取最小必要数据
→ 脱敏
→ 生成项目检查包
→ 调用外部模型API
→ 要求返回结构化JSON
→ 保存问题、建议、数据缺口、评分、原始响应
→ 写入审计日志
→ 用户查看结果。

AI不直接写入合同、发票、成本或税务数据。

## 三、模型和确定性引擎的职责

### 本地确定性引擎
负责：
- 项目利润
- 成本穿透
- ABCD内部交易边界
- 四流匹配
- VAT/CIT管理测算
- EAC
- 风险规则

### 外部模型
负责：
- 解释异常
- 识别逻辑矛盾和遗漏
- 对合同、履约、成本、税务结果进行二次审查
- 根据用户特别要求进行定向检查
- 提出需要补充的数据
- 提出经营和合规建议

模型不得覆盖确定性计算结果。

## 四、模型端点

V2.3实现：

1. `mock`
   - 不访问外网
   - 用于验证完整AI审查流程

2. `openai_compatible`
   - 调用兼容 Chat Completions 结构的模型服务
   - Base URL、路径、模型名称可配置
   - API Key不写数据库
   - 数据库只保存密钥所在的环境变量名

例如数据库保存：

- API Key Env: `TAX_AI_API_KEY`

Mac启动前：

```bash
export TAX_AI_API_KEY="..."
./run_demo.sh
```

## 五、隐私和数据最小化

AI检查不是“把数据库全部发送给模型”。

`build_context()`根据检查范围选择字段。

例如设备检查只发送：
- 设备合同
- 设备履约
- 设备发票
- 设备真实成本
- 设备四流匹配
- 项目必要的总体数字

V2.3已经预留统一 `sanitize_context()` 脱敏入口。

生产版必须继续增加：
- 身份证脱敏
- 银行账号脱敏
- 手机号脱敏
- 姓名可选匿名化
- 单次调用字段白名单
- 外部模型数据发送策略
- 用户发送前预览

## 六、审查记录

每一次AI检查保存：

- 项目
- 检查范围
- 用户特别指令
- 模型端点
- 模型名称
- 创建/开始/结束时间
- 状态
- 输入SHA-256摘要
- 发送数据预览
- 风险等级
- 评分
- Findings
- Recommendations
- Data Gaps
- 原始模型响应
- 调用失败信息

因此同一个项目可以形成连续的AI审查历史。

## 七、用户触发方式

项目页可以直接启动：
- 整个项目
- 成本
- EAC
- 材料
- 劳务
- 设备
- 专业分包
- 税务

四流页可以直接启动：
- 合同
- 履约
- 发票
- 付款
- 整个项目

风险页可以直接启动：
- AI风险复核

也可以进入 `/ai-review` 自由选择范围并输入特殊要求。

## 八、生产化建议

正式版应将长耗时模型调用改为任务队列：

Web
→ 创建AIReviewJob
→ Worker执行
→ 状态轮询/SSE
→ 完成后展示结果

进一步建议支持：
- 一个项目同一环节用多个模型交叉复核
- 关键结论二次模型验证
- Prompt模板版本管理
- 用户角色决定哪些数据允许发送到外部模型
- 模型调用费用统计
- 调用次数/Token统计
- 项目定期AI健康检查

# V0.1扩展：项目体检与整改闭环

V0.1在单次AIReviewJob之上增加：

- `AIReviewBatch`：一次项目体检；
- `AIConsensusReport`：多Scope、多模型结果的本地确定性共识汇总；
- `AIPromptTemplate`：审查Prompt按Scope版本化；
- `RemediationTask`：从检查建议形成整改任务并支持复检。

## 体检编排

`quick / standard / deep`档位自动展开为多个Scope。

同一次体检选择多个模型时：

`Scope × Endpoint → AIReviewJob`

所有子检查完成后，本地共识引擎按Scope聚合共同发现和差异意见。

## 整改闭环

AIReviewJob / AIReviewBatch
→ 用户确认建议
→ RemediationTask
→ 更新业务数据
→ 整改后复检
→ 新AIReviewJob(parent_job_id)
→ 人工verified/closed。

AI不能自动关闭整改任务。
