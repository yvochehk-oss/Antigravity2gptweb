# V2.2 业财税联动设计说明

## 1. 主体边界

系统内固定：
- A：施工企业
- B：劳务公司
- C：商贸公司
- D：设备租赁公司

系统外固定：
- 甲：第三方劳务公司
- 乙：第三方设备租赁公司
- 丙：外部材料供应商
- 丁：外部专业分包/其他供应商

ABCD法律、会计、税务独立；甲乙丙丁只作为外部交易对手。

## 2. 两套利润口径必须同时存在

### 项目综合经营口径
抵消 ABCD 之间内部交易，用 B/C/D 的真实底层成本替代内部采购价，再加 A 自身成本和甲乙丙丁真实外部成本，得到项目真实利润。

### 法人管理口径
A/B/C/D分别按自身开票收入、采购成本、直接成本进行管理利润和税务预测，不使用项目合并抵消结果代替法人账。

这是V2.2最重要的口径分离。

## 3. 四流匹配

系统按“项目 + 交易对手 + 业务类别”汇总：

合同 → 履约 → 发票 → 付款

自动识别：
- 无合同发票
- 付款未见发票
- 履约证据不完整
- 发票超过合同
- 付款超过发票
- 履约结算超过合同

## 4. 成本科目树

当前一级类别：
- material 材料
- labor 劳务
- equipment 设备
- subcontract 专业分包
- project_management 项目管理
- tax 税费

RealCost 同时保存：
- 成本承担法人
- 成本来源/交易对手
- 一级类别
- 子科目
- 期间
- 金额
- 是否为受控体系对外真实支出

## 5. 月度法人税务台账

以“法人 + 月份”生成 A/B/C/D 独立管理台账：
- 销项VAT
- 可抵扣进项
- VAT管理测算
- 开票收入
- 法人账面成本管理口径
- 估算利润
- CIT管理预测

当前CIT只做演示管理预测，尚未包含完整税会差异、以前年度亏损、资产折旧调整等正式申报逻辑。

## 6. 风险中心

风险由确定性规则产生，不由AI自由判断。
V2.2先实现四流差异、履约证据缺失、税率字段异常等基础规则。

## 7. CSV导入

当前支持UTF-8 CSV：
- 发票
- 银行流水

正式版应增加：
- staging暂存区
- 字段映射
- 重复检测
- 人工确认
- 原始文件哈希
- 导入批次回滚
