# Gate S19 — Payment Facts + Legacy CashFlow Map

Status: **IMPLEMENTED / AWAITING LOCAL POSTGRESQL EVIDENCE**

Task19 implements V3 v1.2 Step 12 with additive revision `90_v3_payment_facts`.

## Hard invariants

- `PaymentFact` is CASH basis only. Payment is never cost or accrual recognition.
- Legacy `cashflows` remains readable but is never a canonical CASH fallback.
- Legacy `out`: payer = internal entity, payee = counterparty; legacy `in`: reverse.
- Missing/invalid `transaction_date`, unresolved/ambiguous Party, invalid direction or non-positive amount -> `NEEDS_REVIEW`; no PaymentFact is invented.
- Legacy `period` is never promoted to `transaction_date`.
- `payment_nature` is a business attribute only and does not decide cost category.
- `payment_facts` deliberately has no `project_id`; project/business linkage belongs to later fact/transaction links.
- Group CASH consumes only current VALID `Fact(PAYMENT)+PaymentFact`; internal-to-internal payments are traceable `INTERNAL_CASH_ELIMINATION` components but excluded from external net cash.
