# Gate S16 — Three Basis Separation

Status: **IMPLEMENTED / AWAITING LOCAL POSTGRESQL EVIDENCE**

## Scope

Task16 implements Step 9 of the V3.0 Database Core v1.2 guide without adding a new business table or Alembic revision.

The three analytical bases are explicit code contracts:

- **TAX BASIS** — InvoiceFact, VAT Claim, Tax Prepayment, TaxPayment, TaxRule.
- **ACCRUAL BASIS** — Progress, Settlement, Fulfillment, Accrued Cost, Real Cost; Invoice is supporting evidence only.
- **CASH BASIS** — PaymentFact and TaxPayment only.

## Hard invariants

1. Payment != Cost.
2. Invoice != Revenue Recognition.
3. Invoice Date != Input VAT Period.
4. CASH must not fall back to legacy cashflows before canonical V3 PaymentFact exists.
5. Unknown or prohibited source/role combinations fail closed.

## Implementation

- `app/calc/basis/contracts.py` — basis/source/role contract matrix.
- `app/calc/basis/tax_basis.py` — TAX adapter and claim-period attribution guard.
- `app/calc/basis/accrual_basis.py` — ACCRUAL adapter; Invoice supporting evidence only.
- `app/calc/basis/cash_basis.py` — CASH adapter; explicit fail-closed behavior until PaymentFact.
- `tests/test_v3_three_basis_separation.py` — contract regression tests.
- `scripts/v3/three_basis_gate_16.py` — read-only PostgreSQL Gate S16 verifier.

## Migration decision

No Task16 Alembic revision is created. Step 9 is a calculation-boundary refactor and does not define new canonical business storage. Creating TAX/ACCRUAL/CASH result tables here would duplicate facts and violate the single-fact / deterministic-projection architecture.
