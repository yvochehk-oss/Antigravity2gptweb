# Gate S18 — Canonical Group Penetration

Status: **IMPLEMENTED / AWAITING LOCAL POSTGRESQL EVIDENCE**

Task18 implements V3 v1.2 Step 11 with additive revision `89_v3_group_penetration`.

## Basis separation

- **ACCRUAL** — recursive penetration uses current VALID `FulfillmentFact` edges. Internal operating transfers are eliminated; only external-facing revenue and external leaf cost remain in group gross margin.
- **TAX** — aggregates current official legal-entity `EntityVatLedger` rows. Internal VAT is **not** eliminated.
- **CASH** — intentionally `NOT_READY` until Task19 introduces canonical `PaymentFact`. Legacy `cashflows` are never used as a canonical fallback.

## Hard invariants

1. PostgreSQL `WITH RECURSIVE` is used for operating penetration.
2. Traversal carries `visited`, `path`, `depth` and cycle detection.
3. `External -> B -> A -> Owner` returns external leaf cost only; the B→A operating transfer is an elimination component.
4. `External -> C -> B -> A -> Owner` behaves the same at greater depth.
5. `A -> B -> C -> A` returns `CYCLE_DETECTED` and blocks official APPLY.
6. Legal-entity VAT is preserved in TAX basis; group operating elimination never rewrites Entity VAT / Entity Tax Ledger.
7. Group results are immutable `CalculationRun` projections, not API-time recursive facts.
8. CASH remains fail-closed until PaymentFact exists.
