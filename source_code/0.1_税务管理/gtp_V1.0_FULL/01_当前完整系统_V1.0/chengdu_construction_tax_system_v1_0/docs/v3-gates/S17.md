# Gate S17 — Project Tax Analysis

Status: **IMPLEMENTED / AWAITING LOCAL POSTGRESQL EVIDENCE**

Task17 implements V3 v1.2 Step 10 with additive revision `88_v3_project_tax_analysis`.

## Hard invariants

- Entity VAT Ledger and Entity Tax Ledger never gain `project_id`.
- Project Tax Analysis is TAX basis only.
- Output month comes from `output_vat_period`; Input VAT month comes from `claim_period`.
- Only current CONFIRMED Fact Project Allocations enter official analysis.
- AI-originated allocations must be inserted as CANDIDATE; a human review action may later CONFIRM or REJECT them with review evidence.
- Allocation methods are EXPLICIT / SOURCE_DOCUMENT / MANUAL / PROPORTIONAL / RULE_BASED.
- Signed allocation preserves red/reversal Facts.
- FULL allocation reconciles net/VAT/gross within 0.01.
- PARTIAL remains explicit and is not redistributed; OVER/NONE blocks official PLAN/APPLY.
- TaxPrepaymentFact is already project-scoped and is not reallocated.
- Component lineage may not leak one project's allocation into another.
