# 成都建工 V3.1.0 Windows 桌面控制台 — 发布说明

**发布日期**：2026-09-11  
**分支**：`v3.1-windows`  
**代码基线**：基于 `v3.0-windows` 评审后的工程化加固

---

## 一、 重大变更（Breaking Changes）

无破坏性变更。V3.1 完全向后兼容 V3.0 的所有服务接口与端口协议。

---

## 二、 新增功能（Features）

### 🛡️ CPU 指令集智能路由（P0）
- **新增** `desktop_apps/windows/Services/CpuFeatureDetector.cs`
- 通过 Windows `IsProcessorFeaturePresent(40)` 检测 AVX2 支持
- 自动路由到 `llama-server-avx2.exe` 或 `llama-server-sse42.exe`
- **修复**：老旧 CPU（赛扬/奔腾）报 `0xC000001D` 崩溃闪退的顽疾

### 🌐 WebView2 用户级权限友好检测（P0）
- **新增** `desktop_apps/windows/Services/WebView2Detector.cs`
- HKCU → HKLM 32位 → HKLM 64位 三级降级检测
- 非管理员账户支持 `/per-user` 静默安装
- **修复**：Win10 LTSC 精简版无法启动托盘 UI 的问题

### 🔌 PostgreSQL 动态端口协商（P0）
- **新增** `desktop_apps/windows/Services/PostgreSqlPortNegotiator.cs`
- 54320~54369 端口自动扫描
- `postgres.exe -c "port=<port>"` 免写配置文件启动
- **修复**：多实例并存、端口冲突、只读磁盘部署场景

### 🔁 Watchdog 指数退避 + 熔断机制（P1）
- **新增** `desktop_apps/windows/Services/ServiceWatchdog.cs`
- 5 分钟滑动窗口崩溃计数
- 指数退避：1s → 2s → 4s → 8s → 16s → 30s
- 5 次连续崩溃触发熔断，停止盲目重启
- **修复**：服务反复崩溃时 CPU 占用飙升的风暴问题

### 🌐 老板端前端静态化（P1）
- **新增** `windows_scripts/build_boss_dist.bat`
- 自动检测 dist 缺失 → 自动 `npm run build` → `serve_web.py` 静态伺服
- **修复**：目标机无需安装 Node.js 22.12+ 即可访问老板驾驶舱

### 📦 嵌入式 Python 运行时（P2）
- **新增** `windows_scripts/build_embedded_python.py`
- 体积从 ~3GB 剪裁至 ~600MB
- 优先级链：嵌入式 Python > 服务本地 venv > 旧 RAG venv > 旧 Tax venv
- **修复**：离线部署无需目标机预装 Python

### 📀 单文件 Setup.exe 安装包（P2）
- **新增** `installer/setup.iss` + `installer/build_installer.bat`
- VC++ Runtime + WebView2 依赖前置检测
- 用户数据（数据库）卸载时保留
- 支持 `/verysilent /norestart` 静默安装

## 三、 修复（Bug Fixes）

| 问题编号 | 描述 | 修复方案 |
|---|---|---|
| BUG-001 | 老旧 CPU 启动大模型时崩溃闪退 | CpuFeatureDetector 路由 |
| BUG-002 | 非管理员账户无法检测 WebView2 | HKCU 优先检测 |
| BUG-003 | 54320 端口被占用导致启动失败 | 动态端口协商 |
| BUG-004 | 只读磁盘部署失败 | `-c "port="` 免写配置 |
| BUG-005 | 服务反复崩溃导致 CPU 飙升 | Watchdog 熔断 |
| BUG-006 | 目标机缺少 Node.js 无法访问前端 | 自动构建 dist + 静态伺服 |
| BUG-007 | 离线部署依赖目标机 Python | 嵌入式 Python 运行时 |

## 四、 升级指南

### 从 V3.0 升级到 V3.1

1. **拉取最新代码**：
   ```cmd
   git fetch origin
   git checkout v3.1-windows
   git pull --ff-only
   ```

2. **重新编译**：
   ```cmd
   cd desktop_apps\windows
   dotnet publish -c Release
   ```

3. **构建嵌入式 Python**（一次性）：
   ```cmd
   cd <项目根>
   python windows_scripts\build_embedded_python.py ^
       --source ..\some-venv ^
       --output runtime\python
   ```

4. **可选：构建老板端前端**（一次性）：
   ```cmd
   cd source_code\0.3_老板端安卓App_天府掌舵
   npm install
   npm run build
   ```

5. **编译安装包**（可选）：
   ```cmd
   installer\build_installer.bat
   ```

## 五、 兼容性矩阵

| 组件 | V3.0 | V3.1 | 备注 |
|---|---|---|---|
| PostgreSQL 端口 | 54320 硬编码 | 54320~54369 协商 | 向后兼容 |
| 大模型运行时 | 单一二进制 | AVX2/SSE4.2 双版本 | 需补充 sse42 二进制 |
| 前端运行环境 | Node.js 必需 | 静态 dist 优先 | 旧路径仍可 |
| Python 环境 | 系统 venv | 嵌入式 Python 优先 | 旧路径仍可 |
| WebView2 检测 | HKLM 单一 | HKCU + HKLM | 自动降级 |

## 六、 已知问题与限制

1. **嵌入式 Python 仅 Windows x64**：其他平台仍使用原 venv 路径
2. **大模型 GGUF 权重未打包**：首次运行需执行 `scripts/download_models.py`
3. **Inno Setup 仅生成 Windows 安装包**：macOS/Linux 端使用各自打包脚本
