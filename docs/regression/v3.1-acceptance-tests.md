## 二、 P0-① CpuFeatureDetector 测试

### 测试用例 T-001：AVX2 CPU 路由
**环境**：E1 (i7-10700, 支持 AVX2)

**前置条件**：
- runtime-win-cpu-x64/llama-server-avx2.exe 存在
- runtime-win-cpu-x64/llama-server-sse42.exe 存在

**测试步骤**：
1. 启动桌面控制台
2. 点击"启动全部服务"
3. 观察 `logs/console-YYYY-MM-DD.log` 输出

**预期结果**：
```
[CpuFeatureDetector] 已选择 llama-server-avx2.exe（AVX2）
```
本地大模型端口 8930 健康检查返回 `Healthy`。

**退出码**：0

---

### 测试用例 T-002：SSE4.2 CPU 回退
**环境**：E2 (赛扬 N4100, 不支持 AVX2)

**前置条件**：
- runtime-win-cpu-x64/llama-server-avx2.exe 存在
- runtime-win-cpu-x64/llama-server-sse42.exe 存在

**测试步骤**：
1. 启动桌面控制台
2. 点击"启动全部服务"

**预期结果**：
```
[CpuFeatureDetector] 已选择 llama-server-sse42.exe（SSE4.2）
```
大模型不再因 `0xC000001D` 崩溃闪退，正常进入 LISTEN。

**退出码**：0

---

### 测试用例 T-003：二进制缺失
**环境**：任意

**前置条件**：
- runtime-win-cpu-x64/ 下无任何 llama-server 二进制

**预期结果**：
```
未找到适合当前 CPU 的 llama-server 二进制（检测到 AVX2），
请确保 runtime-win-cpu-x64 目录下存在 llama-server-avx2.exe 或 llama-server-sse42.exe。
```
**退出码**：1

## 四、 P0-③ PostgreSQL 动态端口测试

### 测试用例 T-201：54320 被占用
**环境**：任意

**前置条件**：
- 启动一个 Python `http.server` 占用 54320
- 重启 PostgreSQL

**预期结果**：
```
[PostgreSql] 端口 54320 已被占用（PID xxxx）
[PostgreSql] 已协商端口 54321（尝试 2 次）
[PostgreSql] 已提交 postgres.exe 启动（端口 54321，PID xxxx）
[PostgreSql] 端口 54321 已就绪
```
Python 服务启动时 DATABASE_URL 指向 54321，连接成功。

---

### 测试用例 T-202：54320~54369 全占
**前置条件**：占用 50 个端口

**预期结果**：
```
PostgreSQL 端口协商失败：54320~54369 区间内所有端口均被占用
```
**退出码**：1（覆盖到 RollbackStartedThisRound）

---

### 测试用例 T-203：只读磁盘启动
**环境**：把整个项目目录设为只读

**预期结果**：postgres.exe 通过 `-c "port=<port>"` 启动成功，未触发写 `postgresql.conf` 失败。

## 六、 P1-⑤ 前端 dist 打包测试

### 测试用例 T-401：dist 缺失自动构建

**前置条件**：
- 删除 source_code/0.3_老板端安卓App_天府掌舵/dist/
- 删除 node_modules/

**测试步骤**：
1. 启动控制台
2. 触发 Boss 服务启动

**预期结果**：
```
[Boss] dist 缺失，触发自动构建脚本：...\build_boss_dist.bat
[Boss] 自动构建成功，切换到 serve_web.py 静态伺服
```
或构建失败时：
```
[Boss] 自动构建失败，回退到下一优先级。
[Boss] 回退到 npm run preview（目标机需要 Node.js）
[Boss] npm 命令未找到 → 兜底使用 serve_web.py
```
