# 成都建工控制台（macOS） V3.1

这是一个使用 macOS 原生 `MenuBarExtra` 的菜单栏应用，显示在 macOS 右上角，不显示程序坞图标。菜单栏入口由系统负责在内屏、外接屏和主屏切换时自动布局；应用不会读取或修改菜单栏坐标。

## 构建与运行

在当前目录执行：

```bash
./scripts/build_app.sh
open "build/成都建工控制台.app"
```

应用会按以下顺序寻找项目根目录：

1. `CHENGDU_PROJECT_ROOT` 或 `CDJG_PROJECT_ROOT` 环境变量；
2. 已保存的项目目录；
3. 应用包或当前目录的父级目录中，同时包含 `start_all.sh` 和 `stop_all.sh` 的目录；
4. 如果仍未找到，可在菜单中选择项目目录。

## 菜单功能

- 显示总体状态、本地语言模型、税务系统、资料与知识系统、文档录入引擎、老板驾驶舱状态；
- 每 5 秒检查一次本机健康接口；
- 本地语言模型同时检查健康接口、已加载模型列表、`.local_llm.pid` 与 `llama-server` 进程命令；老板驾驶舱使用项目根目录 `.app.pid` 记录受控前端进程，并核对命令、工作目录和项目归属；
- 打开税务系统、资料与知识系统、老板驾驶舱本地页面；
- 启动全部、重启全部、停止全部业务服务和老板驾驶舱；停止操作保留 PostgreSQL；
- 查看控制台日志、设置登录后自动运行、退出控制台。

核心服务仍只调用项目已有的 `start_all.sh start` 与 `stop_all.sh`，不会自动安装依赖、下载模型或执行迁移。老板驾驶舱优先使用本地 `dist` 的 Vite 预览；没有构建产物时使用已安装的本地 Vite 开发服务，不调用 `npm`/`npx`。停止和重启会对配置的五项服务端口全部监听进程、五个 PID 文件记录及其子进程执行受控清理；清理后检查端口与进程，失败会明确报错；不会按进程名称全局清理其他程序。控制台退出时业务服务继续运行。

## Windows fc7c5ad 对齐保护

- 健康探针请求超时为 **8 秒**，响应达到 **6 秒**才标记为慢响应；慢但健康的服务显示为部分异常/降级，而不是误报为停止。
- macOS `ProcessInspector` 以目标端口、uvicorn 命令和经软链接规范化后的项目工作目录确认归属；Python/uvicorn 可执行文件本身可以位于 Homebrew、uv、pyenv 或其他工作树外路径。软链接项目路径会解析到真实路径后比较。
- 控制台启动确认保护期为 **90 秒**；核心 `start_all.sh` 的 GUI 包装等待窗口为 **600 秒**，避免 BGE-M3/本地大模型加载时被旧的 60 秒 GUI 超时提前判失败。实际服务健康等待仍由 runtime shell 自己的超时策略负责。
- `start_postgres.sh` 使用原子目录锁防止重复自启动。只有在 `postmaster.pid` 的 PID 已死亡且 `pg_ctl status` 也确认数据目录未运行时才自动删除僵尸锁；若 PID 仍存活则 fail-closed，不会冒险删除活动锁。

应用运行不需要在线字体、在线服务或额外运行时依赖。日志只记录控制台动作和结果，不记录脚本输出。
